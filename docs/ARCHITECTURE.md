# Архитектура

Приложение остаётся статическим и не требует сборщика. `index.html` подключает модули в явном порядке. Каждый модуль замкнут в своей области видимости и экспортирует один именованный API; функции интерфейса больше не переопределяют функции игрового расчёта.

## Ответственность модулей

| Каталог          | Что содержит                                                                                                          | Ограничения                                                                            |
| ---------------- | --------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| `src/catalogs`   | Нормализованные расы, миры, специальности, развитие, полковые и технические таблицы                                   | Значения и тексты совпадают с исходной версией; `null` не заменяется придуманной ценой |
| `src/domain`     | Сборка персонажа, XP, покупки/возвраты, валидация, бюджет полка, преобразование полка в происхождение, ксеносы, броня | Не обращается к DOM и localStorage; каталоги передаются движкам                        |
| `src/services`   | Наблюдаемое состояние, структурная проверка сохранений, localStorage, резервная копия, реестр экспортов, XLSX         | Не задаёт игровые эффекты                                                              |
| `src/ui`         | Общие визуальные компоненты, отображение персонажа, фокус, форматирование, выбор режима                               | Получает результаты движков; не считает XP и стоимость                                 |
| `src/features`   | Контроллеры четырёх мастеров                                                                                          | Преобразуют пользовательские действия в состояние, вызывают движки и сервисы           |
| `styles/app.css` | Дизайн-токены, компоненты, адаптивные и печатные стили                                                                | Единственная подключённая таблица стилей                                               |
| `tests`          | Эталоны, поведенческие и доменные проверки                                                                            | Запускаются без браузерного сервера                                                    |

`catalogs/xeno.js` и `catalogs/power-armor.js` сохраняют небольшие адаптеры старых форматов `save/load/installRace`; они делегируют запись сервису хранения. Это явная граница совместимости. Расчёт созданной расы и брони находится в `domain`.

## Персонаж

`KadatCharacter.createEngine(data, advancement, regimentOrigin, regimentCatalog)` создаёт движок с переданными каталогами. Основные операции:

- `createDraft()` — сериализуемый исходный черновик.
- `build(draft)` — вычисленное досье; `breakdown` объясняет вклад каждого источника в каждую характеристику.
- `validate(draft, {baseOnly})` — список `{step, field, message}`. UI переводит на соответствующий этап.
- `transact(draft, action)` — покупка/возврат. Возвращает новый черновик или объяснение отказа; исходный объект не меняется.
- `origins`, `specialties`, `choices`, `skillState`, `costs` — запросы для интерфейса и других клиентов движка.

Черновик хранит исходные выборы и покупки, а не кэш вычисленных ран/XP. `raceId`, `worldId`, `specialtyId` — стабильные идентификаторы; `plannedAdditions` и `rolls` хранят по значению для каждой характеристики. Выборы происхождения отделены от журнала развития. Полковой источник содержит снимок полка и его выборы, поэтому изменение списка сохранённых полков не изменяет персонажа скрыто.

`build` возвращает навыки как `Map`, а черновик остаётся обычным JSON. Сериализовать следует черновик, не вычисленное досье. Внутренние Set/Map контроллера полка преобразуются в массивы снимком `snapshot()`.

## Хранение

| Ключ                               | Формат / назначение                                                              |
| ---------------------------------- | -------------------------------------------------------------------------------- |
| `kadat.regiments.v1`               | Прежний список до 20 полков; поддерживается прежний одиночный `drawbackId`       |
| `kadat.character-origin-source.v1` | Прежний выбранный полк; используется при первом переходе без v2-черновика        |
| `kadat.generated-xeno-race.v1`     | Прежняя созданная раса; структурно проверяется перед установкой                  |
| `kadat.generated-power-armor.v1`   | Прежний формуляр брони; преобразуется в редактируемый черновик при отсутствии v2 |
| `kadat.character-draft.v2`         | `{version: 2, draft, step}`                                                      |
| `kadat.regiment-draft.v2`          | Снимок состояния мастера полка                                                   |
| `kadat.xeno-draft.v2`              | Броски, seed, выборы и этап ксеноса                                              |
| `kadat.armor-draft.v2`             | Выборы компонентов и этап брони                                                  |

Резервная копия имеет оболочку `{format: "kadat-workspace", version: 2, exportedAt, data}`. Импорт проверяет весь документ до изменения состояния; повреждённый документ ничего не заменяет. Можно отменить последнее открытие файла. Отсутствие созданной расы в полной копии удаляет прежнюю созданную расу при восстановлении.

Чтение повреждённой записи возвращает пустой безопасный черновик и сообщение, не удаляя исходную запись. Последующее редактирование сохраняет новый черновик. Отказ записи не уничтожает состояние в памяти: можно скачать JSON. Запись нескольких ключей localStorage не является транзакцией; при отказе хранилища переносите состояние через JSON.

## Расширение

**Новая раса, мир или специальность.** Добавить запись со стабильным ID в каталог и исходные ссылки/описания. Использовать существующие `baseStats`, `statModifiers`, `skills`, `talents`, `choices`, `equipment`, `traits`, `specialRules`. Изменения данных должны сопровождаться отдельно согласованным изменением эталонов; нельзя просто пересчитать контрольные суммы ради прохождения тестов.

**Новый архетип ксеноса или игровой эффект.** Добавить исходные данные в каталог, эффект и проверку в доменный движок, затем необходимые поля выбора в контроллер. Для неструктурированного правила сохранять полный текст до согласования формулы.

**Новая система.** Подключить модуль с собственным состоянием и чистым движком; зарегистрировать показ через `KadatModes.register`. Для резервной копии добавить структурную схему и `snapshot/restore` в сервис рабочей области. При несовместимом изменении формата нужна явная миграция версии.

**Новый формат экспорта.** Зарегистрировать адаптер `KadatExports.register(id, {download})`, который принимает вычисленное досье. Игровую логику не копировать в экспорт. XLSX умеет отдельно строить байты `buildWorkbook(character)` для тестов и других способов сохранения.

**Новые предметы.** Полковой каталог уже имеет стабильные ID, цены, текст эффекта и ссылки на исходную таблицу. Сейчас личная экипировка персонажа в основном текстовая. Структурированные модели оружия и брони — отдельная миграция следующего этапа; текущий интерфейс не выводит вымышленные массы, урон или защиту из названия предмета.

## Проверки и выпуск

`npm test` и `npm run format:check` — обязательные проверки ветки. Для изменения правил сначала согласовать правило и независимый ожидаемый результат. Перед публикацией дополнительно пройти браузерную матрицу из отчёта. Файлы исходного packed-кода и многослойных тем доступны в Git-истории `c04816b`, в новой странице они не нужны.
